## 1. 产品与受众

一款单一用途的瓷砖用量计算器 App。输入房间尺寸和瓷砖规格，输出要买多少片、多少箱、花多少钱。

**用户是谁**：美国及英语市场的瓷砖工、装修承包商、DIY 房主。一半是职业工人，一半是周末自己动手的人。

**市场验证（v2 新增）**：品类头部 app（10 万+下载）仅支持小数输入、无缝宽、无图案，其最高赞评论全是"功能太浅"的差评；12 个同类 app 无一支持英尺-英寸-分数输入。本 brief 的差异化方向已被评论区证实是真实需求。

**这个界面的唯一任务**：让一个人在工地上、单手、可能戴着手套、可能在强光下，三十秒内算出该买多少瓷砖。

**使用场景的物理约束**（这些直接决定设计，不是修辞）：
- 强光下看屏幕 → 需要高对比度，浅色模式是主场景
- 手脏、戴手套、单手操作 → 触控目标大，关键操作在拇指可达区
- 环境嘈杂、注意力被打断 → 结果必须一眼可读，状态必须自解释
- 工地没信号 → 全离线，界面里不能有任何"加载中""同步"的概念

## 2. 风格方向

### 定下来的部分

界面气质应该像**一件工具**，不像一个 SaaS 产品：结实、清晰、克制、可信。用户信任它是因为它看起来不会算错。

（v2 补充一个反面对照：品类头部竞品是 WebView 网页套壳，表格式输入、网页感十足。我们要的"原生工具感"正好是它的反面。）

灵感来源请从这个行业本身的物料里找，而不是从通用 App 设计里找：瓷砖的模数网格、勾缝的间隙、粉线、卷尺的刻度、水平仪的气泡、锯齿抹刀的齿距。

### 交给你决定的部分

配色、字体搭配、以及那个"签名元素"由你判断。但有两条要求：

**一个建议方向（可采纳可推翻）**：把瓷砖网格本身做成结构语言。结果卡或输入区的背景可以是一层极淡的模数网格，网格的缝隙宽度对应用户输入的 grout gap——这样一个纯装饰性的图形就变成了在传达真实信息的东西。如果你有更好的想法，推翻它，但要说明理由。

**必须避开的三种套路**（这三种是当下 AI 生成设计的默认长相，用了就露馅）：
1. 米白背景（#F4F1EA 一带）+ 高对比衬线标题 + 陶土橘点缀
2. 近黑背景 + 单一亮酸绿或朱红点缀
3. 报纸版式：发丝线分割、零圆角、密集多栏

### 排版的功能性要求（不是风格偏好，是硬约束）

- **所有数字必须用等宽数字（tabular figures）**。结果会随输入实时变化，非等宽数字会导致数值跳动，在这个产品里是硬伤。
- 结果区的主数值（Tiles needed）要能在**一臂距离**看清。
- 英制尺寸的显示形如 `12' 3-1/2"`，撇号、引号、连字符的排版细节要处理好，不要用直引号糊弄。
- **（v2.1）短字符串要为翻译膨胀留余地**：产品将本地化到德语/法语/西语等（德语平均 +30–40%，且字符串越短膨胀越大——10 字符以内的按钮文案可能翻倍）。chips、分段控件、按钮、表头都不能按英文文案的紧身尺寸设计，要么预留 ~2 倍宽度，要么定义清楚降级规则（换行 / 缩字 / 截断优先级）。

## 3. 屏幕清单（需要交付的画面）

按优先级排序，1-3 是核心：

### 3.1 主计算页 · 手机竖屏 · 键盘收起

自上而下的信息结构：

- **Areas**（区域列表）：每行两个尺寸输入框，行尾实时显示该区域面积。可增删，列表最多 20 行。行尾有删除入口。
  - **（v2 新增）扣除区域**：用户需要从铺贴面积中扣掉门、窗、橱柜等不铺的部分。列表底部两个入口：`+ Add area` 和 `+ Add cutout`。cutout 行的面积显示为负值（如 `−12.50 ft²`），并需要一眼可辨的视觉区分（不要只靠一个负号）。具体交互形式（独立分组还是行内标记）由你判断，但语义必须清晰：净面积 = areas 之和 − cutouts 之和。
- **Tile size**：预设 chips 横向排列 + 一个 `Custom` 项。英制预设：`4×4`、`6×6`、`12×12`、`12×24`、`18×18`、`24×24`、`24×48`（单位 inch）。选中 Custom 时下方展开两个尺寸输入框。
- **Grout gap**：单个小输入框，默认 `1/16"`。（这是竞品评论区被点名最多的缺失参数——14 赞 + 11 赞两条评论专门要它，是我们的核心卖点之一，视觉上不要把它藏起来。）
- **Layout pattern**（损耗率）：四选一的分段控件，选项文案为 `Straight`（默认）、`Diagonal`、`Herringbone`、`Custom`。每个选项下方或旁边要显示对应的损耗百分比：10% / 15% / 20% / 自定义。选中 Custom 时展开一个 0–30% 的滑块。（可选加分：每个选项配一个极小的铺法示意图形，参考瓷砖行业图册的画法；有竞品用图案示意图，用户理解成本明显更低。）
- **Boxes & cost**（可折叠，默认收起）：`Tiles per box`、`Price per box` 两个输入。
- **结果卡**：见 3.4。
- **（v2 修改）广告位**：屏幕最底部常驻一条 anchored adaptive banner。设计时按 60dp 高预留占位块，但布局要容忍 50–70dp 浮动（adaptive banner 高度由设备决定）。**硬约束：banner 与其上方任何可交互元素之间必须有肉眼可辨的分隔（间距 + 表面色差或描边），这是 AdMob 误触政策的硬性要求，被判违规会限流。**
- 顶部导航栏：左侧标题 `Tile Calculator`，右侧两个图标入口（History、Settings）。

### 3.2 主计算页 · 手机竖屏 · 英制分数键盘展开（**这是整个设计的重点画面**）

这是产品的差异化所在，竞品普遍只支持小数输入，美国工人的思维是 `5 ft 3-1/2 in`。键盘是自定义的，不用系统键盘。

布局结构固定如下，你负责把它做好看、好按：

```
┌─────────────────────────────┐
│  1/16  1/8   1/4   1/2      │   ← 分数快捷键第一行
│  3/16  3/8   3/4   7/8      │   ← 分数快捷键第二行
├─────────────────────────────┤
│   7     8     9     ⌫       │
│   4     5     6     ft      │
│   1     2     3     in      │
│   0    Clear  Next  Done    │
└─────────────────────────────┘
```

设计要点：
- 所有按键触控目标不小于 48×48dp
- 三类按键（数字 / 分数 / 功能）要有清晰的视觉层级区分，`Done` 是主操作
- 分数键是可切换状态的：选中后要有明确的激活态，再点一次取消
- 键盘弹出时，**当前正在编辑的输入框必须可见**，不能被键盘遮住；正在编辑的字段和当前处于 feet 段还是 inch 段，都要有可见提示
- **（v2 强化）键盘位于 banner 广告之上，两者不重叠，且键盘最底行（尤其 `Done`）与 banner 之间必须有明确的分隔带**——这是本产品最大的广告政策风险点：误触判定的头号场景就是"底部键盘紧贴 banner"。这条间隔宁可牺牲一点屏效也要保住，请把它设计成看起来是有意为之的结构（而不是尴尬的空白）。

### 3.2b 公制键盘变体（v2.1 新增）

产品将本地化到公制市场（拉美/欧洲/东南亚/中东等），公制用户看到的是这个键盘。与 3.2 同一套视觉语言，差异如下：

```
┌─────────────────────────────┐
│   7     8     9     ⌫       │
│   4     5     6     m       │
│   1     2     3     cm      │
│   0     .    Next  Done     │
└─────────────────────────────┘
```

- **没有分数快捷键区**——键盘整体更矮，内容区相应变高，两种键盘高度不同是预期行为，布局要能适应
- 单位键：房间尺寸惯用 `m`，瓷砖尺寸惯用 `cm`，缝宽惯用 `mm`。默认单位随当前编辑字段自动带出，键上的单位键用于临时覆盖。`Clear` 若放不下可移入长按 ⌫ 或由你另行安排，说明理由即可
- **小数分隔符键的键帽按地区显示 `.` 或 `,`**（巴西/欧陆大部/印尼/越南/土耳其用逗号）。设计稿出 `.` 版即可，但 token/规格里注明这个键帽是可变的
- 交付一张：手机竖屏、浅色、键盘展开态，等价于 3.2 的公制版本

### 3.3 主计算页 · 平板/iPad 横屏 · 双栏

断点是 600dp。宽度 ≥ 600dp 时切双栏：

- 左栏：输入表单 + **常驻键盘**（不弹出，固定显示在左栏底部，按键尺寸放大到 56dp）
- 右栏：结果卡常驻，输入变化即时重算
- banner 仍锚定屏幕最底部，横跨全宽（与可交互元素的分隔约束同 3.1）

同一套设计要能在 iPad 分屏到 1/3 宽度时优雅退化成 3.1 的单栏形态。

（市场情报：App Store 全品类的瓷砖/建筑计算器都只是"放大的手机版"，没有一款做过真正的 iPad 分栏布局——这张画面做好了是商店里的独一份卖点。手机稿 Android/iPhone 通用，无需分开出稿。）

### 3.4 结果卡的三种状态

这是用户真正来看的东西，值得单独设计：

**空状态**：文案 `Enter dimensions to see results`。这是一个邀请，不是一个错误，语气要中性。

**完整状态**，层级从主到次：
- `Total area` — 例：`120.00 ft²`
- `Tiles needed` — **最大最重的数字**，例：`132`
- 次要说明行，灰色小字：`120 tiles + 10% waste`
- `Boxes to buy` — 例：`17`
- `Estimated cost` — 例：`$425.00`

后两项在用户没填箱规/单价时整行隐藏（不是显示占位符或 `--`）。

**（v2 新增，可选加分项）迷你铺贴预览**：竞品最高赞差评之一是 "I cannot see the layout"。如果 §2 的"签名网格"方向被采纳，可以把它升级为传达真实信息的迷你预览：结果卡背景或角落的网格随所选 pattern 改变排布方向（straight 正铺 / diagonal 斜 45° / herringbone 人字），缝隙宽度对应 grout gap。不追求精确制图，追求"一眼确认我选的是这种铺法"。如果这会让结果卡变吵，宁可不做——数字的可读性优先级永远最高。

**小面积提示**：总面积小于 2 m²（约 21 ft²）时，卡片底部多一行提示 `Small areas produce more cut waste — consider +5%.` 这是建议不是警告，不要用错误色。

### 3.5 History 页

倒序列表，每条显示：面积 → 片数/箱数的摘要，加相对时间（`2 hours ago`）。点击整条恢复到输入表单。左滑删除，右上角清空全部。空状态文案：`Your calculations will appear here.`

（背景信息：有竞品把"免费版限存 10 条"做成付费点。我们相反——历史记录无限免费，这是针对它的定位打法，所以 History 页不需要任何数量限制、升级提示的 UI。）

### 3.6 Settings 页

条目：`Units`（Metric / Imperial 二选一）、`Language`（默认 `System`，展开为产品支持的语言列表——多语言 app 必备，发展中市场大量旧设备没有系统级 per-app 语言设置）、`Currency symbol`（文本输入，默认 `$`）、`Appearance`（跟随系统）、`Privacy policy`、`Rate this app`、`Version`。

### 3.7 深色模式

至少给 3.2（键盘展开态）和 3.4（结果卡）出深色版本。深色不是把颜色反相，重新校准对比度和层级。

### 3.8 隐私同意首屏（次要，但请给一版）

首次启动向 EEA 用户展示的广告同意说明屏，以及 iOS 上的 ATT 前置说明屏。这类屏幕的转化率直接影响收入，但绝大多数独立开发者随手糊弄。要求：诚实、简短、不用深色模式诱导按钮（dark pattern），说清楚"广告让这个 App 保持免费"。

### 3.9 App 图标方向（加分项）

商店里的图标是转化率的第一道关口。给 2–3 个方向，要求：在 48px 下仍能辨认，不用文字，和"瓷砖 + 计算"的语义直接相关，且不能撞上现有那一堆蓝色齿轮/房子图标。

### 3.10 阿拉伯语 RTL 样张（v2.1 新增，硬需求）

阿拉伯语市场（埃及/沙特/海湾/北非）是确认要做的目标市场。给 3.1（主计算页、键盘收起、浅色）出一张阿拉伯语 RTL 版本。界面文字用阿拉伯语（机器翻译占位即可，这张验证的是布局，不是文案）。

**镜像的**：整体布局方向、导航栏（标题靠右，History/Settings 图标靠左）、区域列表的行结构（删除入口移到左侧）、结果卡的标签-数值对齐、`+ Add area` 等行内元素顺序、一切方向性箭头。

**不镜像的**（请在稿子里显式标注，这是给开发的防坑标记）：
- **数字本身与数字键盘的键位排列**——阿拉伯语系统计算器和拨号盘的 1-2-3 顺序与 LTR 完全一致，镜像键位是经典错误
- **尺寸表达式**：`60 × 120`、`3.5 m` 这类数字+单位串整体保持 LTR 内部顺序
- 与方向无关的图标（设置齿轮等）

**数字系统**：一律用西方数字 0-9（阿拉伯市场数字化场景的主流用法，马格里布地区更是只用西方数字）。东阿拉伯数字 ٠١٢٣ 未来做成设置项，设计稿不用出。

**字体**：Noto Sans Arabic（与拉丁主字体做同族搭配，见 §4）。

### 3.11 中文样张（v2.1.x 新增）

给 3.1（主计算页、键盘收起、浅色）出一张简体中文版本，与 3.10 同为「界面文案一律英文」的例外。目的是验证 CJK 排版：

- **字体**：Noto Sans SC，与拉丁主字体搭配；**数字、单位、尺寸表达式仍走拉丁字体的等宽数字**（`120.83 m²` 不用全角字符）
- **中文文案普遍比英文短 30–50%**——验证 chips、按钮、标签在"短文案"下不显得空旷失衡（这是与德语膨胀相反方向的压力测试）
- 场景数据用**公制**（中文用户全部在公制世界），键盘形态即 3.2b 公制键盘
- 文案翻译用地道的装修行业用语（如 grout gap → 留缝宽度、waste → 损耗），不要机翻腔

## 4. 必须交付的设计 token（**这一项比视觉稿本身更重要**）

最终这套设计要落到 Flutter 上实现，所以请**用 Material 3 的角色命名**输出完整 token 表，这样能直接映射到 `ThemeData`：

**颜色**：给出种子色，以及浅色/深色两套完整的 `ColorScheme` 角色值（`primary`、`onPrimary`、`primaryContainer`、`surface`、`surfaceContainerLow/High`、`onSurface`、`onSurfaceVariant`、`outline`、`outlineVariant`、`error`）。全部标注十六进制值，并注明关键文本组合的对比度是否达到 WCAG AA（工地强光场景下，正文对比度建议做到 7:1 而不是及格的 4.5:1）。

**字体**：按 Material 3 的 `TextTheme` 角色给出（`displayLarge` 到 `labelSmall` 里你实际用到的那些），每个角色标明字号、字重、行高、字间距。明确指定哪些角色启用等宽数字。字体请从 Google Fonts 里选，标注具体名称。
（v2.1 附加约束）产品要扩展到阿拉伯文/天城文（印地语）/泰文/中文，主字体选择需考虑多文字搭配：要么验证所选拉丁字体与 Noto Sans Arabic / Noto Sans Devanagari / Noto Sans Thai / Noto Sans SC 的搭配协调性（x-height、字重、灰度），要么直接用 Noto Sans 系一步到位。等宽数字始终由拉丁字体承担——印地语/泰语/中文界面实际也用西方数字 0-9，这条不因语言而变。泰文默认行高偏大，`TextTheme` 的行高取值要按泰文上限校验，避免非拉丁语言下行间挤压。

**间距**：以 4dp 为基数的梯度（4/8/12/16/24/32/48），并说明各梯度的使用场景。

**圆角**：一套半径梯度，以及"哪类元素用哪一档"的规则。

**其他**：最小触控目标尺寸、分割线策略（用描边还是用表面色差）、动效时长与缓动曲线（键盘弹出、结果数值变化、区域行增删这三处）。

## 5. 边界条件

- 不要设计任何需要联网、登录、账号、云同步的东西。这个 App 完全离线（广告是唯一联网行为，且不体现在 UI 里）。
- 不要设计引导页/onboarding 流程。用户搜到它就是要立刻算数的，教程是摩擦。
- 不要用 emoji 做图标。
- 不要出现"AI"字样或相关视觉暗示。
- 设计稿主画布仍用英制/英文场景填充（美国是首发市场）；公制世界由 3.2b 键盘变体覆盖，RTL 由 3.10 覆盖，CJK 由 3.11 覆盖。单位默认值随地区自动带出（美国/加拿大英语区默认英制分数，英国默认公制 mm，印度英语区默认英制 sq ft 场景，其余默认公制），UI 上始终允许手动切换单位制。
- **（v2.1）所有数字、尺寸表达式在任何语言下保持 LTR 顺序和西方数字 0-9**；小数分隔符与千分位按地区渲染（巴西显示 `1.234,56`）。设计稿只出 `.` 版本，规格里注明分隔符可变。
- 遵守可访问性底线：键盘每个按键有语义标签，焦点态可见，尊重系统的减弱动效设置。
- **（v2 新增）banner 广告与任何可交互元素之间必须有明确视觉分隔**（AdMob 误触政策，违规会被限流），所有含 banner 的画面都要体现这条。
- **（v2 新增）插屏广告不需要出设计稿**（它是 AdMob 全屏接管渲染的），但流程上要知道它只会出现在一个位置：用户查看完结果、点"新建计算"之后。所以"完成一次计算"要在交互上是一个清晰的自然断点，而不是无边界的连续编辑。不设计任何退出挽留、启动等待类的界面。

## 7. 附录：给设计师的竞品证据（2026-07 调研）

**你在为一个真实的市场空位做设计。** 以下是证据，帮助你理解每个设计决策背后的分量：

**品类头部长什么样**：美区搜索第 1 名（10 万+下载、4.1 分）是一个 WebView 网页套壳——表格式输入、网页按钮、底部导航 + banner 挤在一起。它 2018 年上架后几乎没再进化。我们要的"原生工具感"是对它最直接的差异化。

**用户的原话**（来自头部竞品的高赞评论，可以直接当设计验收标准用）：
- "Doesn't allow you to choose an orientation of tiles or a special pattern... It's essentially the same as using a calculator"（22 赞）→ 我们的 Layout pattern 控件要让人一眼看出"这不是普通计算器"
- "does not account for width of spacing"（14 赞）/ "please add a clearance option... a gap between 2 tiles"（11 赞）→ Grout gap 输入是明星参数，别藏
- "I cannot see the layout"（多条）→ 3.4 的迷你铺贴预览回应的就是这条
- "I Like the app I just don't like the ads"→ 广告位要克制、有边界感，让人觉得"它守规矩"
- 好评侧："Just nice works offline"、"Makes my job calculation so much faster"→ 快、准、离线是留人的根本，任何装饰不能拖慢这三件事

**做得好的竞品参考**：另一个功能强但没人发现的竞品（500 安装）用 7 张铺法示意图（herringbone/basketweave 等）做图案选择，理解成本显著更低——3.1 里 pattern 选项配小图示的建议来自这里。

**iPad 情报（v2.1 新增）**：App Store 上没有任何一款瓷砖/建筑计算器做过真正的 iPad 布局（全是放大的手机版）——3.3 的双栏设计是全品类空白，值得作为独立卖点认真做。

**损耗率数字的出处**：行业通行两套口径（5/10/15 或 10/15/20），本 brief 用保守的 10/15/20，对 DIY 用户更安全，设计稿照用即可。
